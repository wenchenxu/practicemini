# 2026-10-14

## 合同到期提醒 + 合同中心 Tab 重构（已完成，待部署云函数）

业务需求：合同快到期/已过期时业务员看不到，需要提醒；不要弹窗（多业务员、提醒后不易定位合同）。

### 方案（已实现，非弹窗）
- 合同中心 Tab 收缩为合同状态轴：`生效中(默认) | 到期提醒 | 已结束 | 全部`，签署状态不再做独立 Tab。
- "到期提醒" Tab = 到期日距今 ≤30 天 + 已过期未终结的合同；**服务端查询**（修复原来客户端过滤的分页陷阱）；按到期日升序排序 → **已过期自动置顶**。
- 每项显示倒计时标签：`已过期 X 天`(红) / `今天到期`(红) / `剩 X 天`(橙)，判定基准 = 到期日 06:00(UTC+8)，与 AutoReturn 一致。
- `长期有效` 合同不进入提醒栏（字符串比较天然兼容，'长期有效' > 任何 YYYY-MM-DD）。

### 数据层闭环（合同离开"到期提醒"的条件）
- 退租：车辆中心"退租解绑" → vehicleOps rent_end 标记 `terminated`（原有）。
- 续租：contractV2 **新增逻辑**——新合同创建后事务外终结同车牌旧合同（同司机 → `renewed`，换司机 → `terminated`），写 `replacedByContractId`。失败仅记日志不影响主流程。**这是本次最重要的数据层修复**，否则续租后旧合同永远留在提醒栏。
- 确认收车：AutoReturn 每天 00:05 把到期车辆自动回库并标记合同 `expired`；业务员联系司机后，列表项红色"确认收车"按钮 → contractOps 新增 `terminate` action（仅允许 expired/动态过期状态终止，车辆仍在租的拒绝并提示去车辆中心办理）。

### 签署状态角标

### contractStatus 状态机（最终）
- 无值 / `active`：生效中（旧数据无值，前端按 contractValidPeriodEnd 动态判断是否过期）
- `expired`：已到期（AutoReturn 自动回库标记，待人工处理）
- `terminated`：退租（手动退租解绑 / 人工确认收车）
- `renewed`：已续租（contractV2 续租/重租时标记旧合同）

### 到期窗口天数外置到云函数（避免小程序发版）
- `EXPIRING_WINDOW_DAYS = 30` 从前端硬编码改为 contractOps 云函数顶部常量，通过 `action:'getConfig'` 返回。
- 前端 contract-list onLoad 调 `loadExpiringWindow()` 拉取，存 `data.expiringWindowDays`，fetch/decorateContractItem 运行时引用 `this.data.expiringWindowDays`。
- 前端保留 `DEFAULT_EXPIRING_WINDOW_DAYS = 30` 作兜底（云函数调用失败时用），data 初始化用此常量。
- 调整窗口只需改 contractOps 常量 + 重新部署云函数，**无需小程序审核**。
