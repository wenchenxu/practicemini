# 2026-10-15

## 状态机 v2 + 签署状态自动同步（已完成，待部署）

用户痛点：①过期几十/上百天的合同堆在提醒栏（存量数据从未被终结）；②签署状态依赖手动刷新导致失真（真逾期被当待签 / 真已签显示待签）；③起草重做的废合同挂"生效中"。用户提出"每辆车最新合同即有效合同"思路 → 确立为系统核心不变式。

### 核心设计：一车一当前合同（不变式）
- 每车牌（fields.carPlate）createdAt 最新的非软删合同 = 当前合同，其余一律终态。
- **用 createdAt 而非起始日期**（起始日期是表单字段可编辑；起草重改正日期的场景会误判）。
- swapVehicle 场景验证过：swap 原地改 carPlate，旧合同与新合同同组被正确终结。

### contractStatus v2
- active/expired/terminated（真实退租·确认收车）/ renewed（同司机新合同替代）/ **superseded（新增：换司机替代或起草重做，文案"已替代/已作废"，灰色）**
- contractV2 换司机场景原写 terminated，本次改为 superseded。

### 不变式三重保障
1. contractV2 创建后终结同车牌旧合同（已有，terminated→superseded 一行改动）
2. **AutoReturn 自愈**（新增）：每天扫描 rented 车辆时顺手终结该车其他非终态旧合同（防御任何路径漏终结）
3. **rebuildContractStatus**（新增维护工具）：vehicleOps 手动调用（用户明确只要云函数入口，不加 dev-tools 按钮）：
   - `{ action:'rebuildContractStatus', payload:{ dryRun:true } }` 预览
   - `{ action:'rebuildContractStatus', payload:{ dryRun:false } }` 执行
   - 幂等；当前合同过期重算（06:00 规则）→ expired；旧合同同司机→renewed/换司机→superseded

### AutoReturn 选合同逻辑修复（重要）
- 原来用 esign.signTaskStatus（revoked/task_terminated/abolishing 排除）挑合同——依赖人工刷新的"脏"字段做回库决策，正是签署状态失真问题的又一危害。
- 改为 contractStatus 轴（active/expired/无值取最新，含 expired 保幂等）。
- 两个定时器（AutoReturn 00:05 / 签署同步 07:30）从此零耦合，顺序无关。

### 签署状态自动同步（api-fadada）
- 新增 `syncPendingSignTasks(payload)`：查"当前合同 + signTaskId 存在 + 状态非终态"（终态=task_finished/task_terminated/revoked/expired/abolishing），逐个调 ECS getSignTaskDetail 回写，有变化才写库。防御上限 500 条。
- ECS 返回解析：`resp?.raw?.data?.signTaskStatus || resp?.detail?.signTaskStatus`。
- **定时器**：config.json 加 triggers `syncSignTasks` cron `0 30 7 * * * *`（07:30，业务员上班前）。main 入口 Timer 拦截。⚠️ 必须单独「上传触发器」。
- **入口同步**：前端 onLoad 后台静默调（cityCode 限定），30 分钟节流（storage: lastContractSignSyncTs），updated>0 时静默 refresh。手动"刷新状态"按钮保留兜底。

### 前端三色角标

- SIGN_BADGE_WARN 移除 expired 键，'expired'→'已逾期' 单独处理。
